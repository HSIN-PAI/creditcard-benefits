# 💳 信用卡權益百科

查詢自己持有的台灣信用卡回饋權益的單頁工具，適合部署在 GitHub Pages。

## 專案結構

| 檔案 | 用途 |
|---|---|
| `index.html` | 前端頁面（UI 與渲染邏輯，**不含卡片資料**） |
| `data.js` | 所有卡片權益資料（給人讀的敘述），更新權益只需要改這個檔 |
| `rules.js` | 推薦引擎的結構化規則（通路→回饋率→條件→封頂→起訖日）＋通路字典 |
| `engine.js` | 「這筆刷哪張」推薦引擎（查詢解析、規則比對、封頂試算，純瀏覽器端） |
| `scripts/check_benefit_pages.py` | 抓取各銀行官方權益頁、比對內容是否異動 |
| `.github/workflows/benefit-watch.yml` | 每週一自動執行監測，有異動就開 Issue 提醒 |
| `.watch/hashes.json` | 各權益頁面上次抓取的內容指紋（機器自動維護） |

## 這筆刷哪張？（推薦引擎）

頁面最上方輸入「通路 + 金額」（例：`全聯 1200`、`日本 5000`、`line pay 500`），
引擎會列出每張卡的預估回饋、實質回饋率、封頂餘裕與條件標籤（需切方案／需領券／需登錄等），
點擊結果可展開該卡完整權益。全部在瀏覽器端計算，無任何後端。

設計原則（v1）：

- **常態權益結構化**：規則存在 `rules.js`，含通路字典（別名比對，支援分類查詢如「超商」「網購」）
- **領券／登錄做成條件標記**：引擎只提醒「這筆要先領券」，不假裝知道你領了沒
- **限時活動掛起訖日**：過期規則自動失效；75 天內到期會顯示倒數
- **誠實原則**：通路認定太模糊的權益不入規則（寧缺勿錯）；被排除的通路會明說；
  封頂餘裕以「當期未刷過」計算並註明假設
- 引擎的等級假設（CUBE Level、DAWHO 等級…）在 `rules.js` 開頭的 `SETTINGS` 調整

**更新權益時：先改 `data.js`（給人讀），再同步 `rules.js`（給引擎算）。**

## 權益資料怎麼「自動更新」？

信用卡權益沒有公開 API，銀行只會在官網公告，所以完全自動改寫資料並不可靠。
本專案採用「**自動監測 + 人工確認**」：

1. GitHub Actions 每週一早上抓取 `data.js` 中每張卡的 `officialUrl` 頁面內容
2. 內容與上次不同 → 自動開一個 Issue，列出哪幾張卡的頁面變了
3. 收到 Issue 後，到官方頁面確認新權益，更新 `data.js` 對應卡片即可
4. 頁面右上會顯示更新日期；超過 45 天未更新會出現提醒橫幅，每張卡也會顯示權益到期倒數

也可以到 repo 的 Actions 頁面手動觸發「權益頁面異動監測」。

## 更新資料的方式

編輯 `data.js`：

- `meta.updated`：改成當天日期
- `meta.period`：權益適用期間（例如 `2026/07/01 - 2026/12/31`）
- 每張卡片欄位：
  - `rate` / `note` / `tags`：列表頁顯示的摘要
  - `validThrough`:權益截止日（頁面會自動顯示倒數與到期警示）
  - `warning`：注意事項（黃色框）
  - `caps`：封頂試算（綠色框）
  - `sections`：詳細通路說明
  - `officialUrl`：官方權益頁（同時是異動監測的目標）
  - `lastVerified`：這張卡最後查證日期

改完 push，GitHub Pages 就會更新。
